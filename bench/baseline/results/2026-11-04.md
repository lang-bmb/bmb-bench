# Rust baseline (2026-11-04)

- Environment: Intel(R) Xeon(R) Processor @ 2.10GHz (4 cores), Linux-6.18.44-fc-v233-x86_64-with-glibc2.39
- Tools: rustc 1.97.0 (2d8144b78 2026-07-07); Ubuntu clang version 18.1.3 (1ubuntu1); bmb `build` (clang -O2)
- Method: the median (wall clock) of 15 interleaved runs per variant. Measured after the outputs were checked to agree.
- A ratio < 1 means BMB is faster.

## Interpretation

- Load: nothing else ran on the same machine during the measurement (1-minute load average 0.01 at the start). The absolute times are 20 to 40% longer than on 10-24. It is another host with the same CPU label, so absolute times are not compared and only the ratios are looked at.
- All 7 are within ±5% of safe Rust (0.962 to 1.041; on 10-24, 0.869 to 1.019). The changes to the generated code in between (the trap path `bmb_trap` and others) do not show in the ratios.
- The difference between safe Rust and unchecked Rust is at noise level this time too (only in vadd is unchecked slower). The interpretation of 10-24 stands.
