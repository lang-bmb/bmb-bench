# Library speed and size (2026-11-02)

- Environment: Intel(R) Xeon(R) Processor @ 2.80GHz (4 cores), Linux-6.18.44-fc-v185-x86_64-with-glibc2.39
- Tools: rustc 1.97.0 (2d8144b78 2026-07-07); Ubuntu clang version 18.1.3 (1ubuntu1); bmb `build` (clang -O2)
- Method: the median (wall clock) of 15 interleaved runs per variant. Measured after the outputs were checked to agree. Size is that of the stripped executable.
- Compared with: for utf8, the Rust standard library's `std::str::from_utf8`; for sha256, safe Rust of the same algorithm (standard library only) and the `sha2` crate 0.11.1 (`cargo build --release --locked`, opt-level 2). SHA-NI on this CPU: absent (the software implementation of the crate).
- A ratio < 1 means BMB is faster.

| Bench | Compared with | BMB ms | Other ms | BMB/other | BMB bytes | Other bytes |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| utf8 | `std::str::from_utf8` | 1392.5 | 1599.9 | 0.87 | 14512 | 343768 |
| sha256 | Rust of the same algorithm | 988.8 | 977.5 | 1.011 | 14512 | 345952 |
| sha256 | the `sha2` crate | 988.8 | 785.0 | 1.26 | 14512 | 356136 |

- Load: during the run a repeated-run measurement (mostly waiting for the model, now and then a proof of the judge) ran on the same machine (1-minute load average 1.1 to 1.3). A first run of the same day, measured at a load average of about 5, was thrown away (sha256 BMB 1,128 ms, 1.25 times the Rust of the same algorithm: even with interleaved order the load falls differently on each variant).
- Reading: BMB's SHA-256 is on the level of safe Rust of the same algorithm (1.01 times; 1.02 times on 2026-10-28), and the software implementation of the `sha2` crate is 1.26 times faster than BMB. The crate unrolls the rounds and overlaps the schedule computation with the rounds. The BMB code is proved as small functions in the shape of the FIPS specification (`lib/sha256.bmb`), and changing that shape means redoing the proofs. Size: 14,512 bytes for BMB against 356,136 bytes for the crate (stripped).
